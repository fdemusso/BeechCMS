# Sprint Plan — DataTable Column Resizing & Density

> Generated by Stage 01 (Sprint Planning). Scope locked to the `feature_brief.md`
> deferred item *"Column Resizing & Density"*. **Dashboard-only by construction.**

==========================================================================
SECTION 1 — WHY THIS SPRINT EXISTS FIRST
==========================================================================

The DataTable cell-rendering sprint shipped everything *inside* the cell (truncation,
badges, tones, ratings) but explicitly deferred everything about the cell's **container
geometry**: how wide a column is and how tall a row is. This sprint closes that gap. It is
the natural next step because column width and row density are the last two pieces of
table layout still hard-coded — `data-table.tsx` ships a single frozen `ROW_HEIGHT_PX = 48`
and lets TanStack auto-size every column. Until both are user-controllable, the "Visible
columns" and "Rows-per-page" controls already present in the settings menu describe an
incomplete layout story.

**Adherence to the Botanical Engine invariants.** This sprint never touches the Botanical
Dialect. Column width and density are *presentation-only* state. There is **no** new D1
column, **no** `apiToDb`/`dbToApi` change, **no** new field on the `Seed`. The Botanical
Invariant is satisfied trivially because the database is never consulted: a column's pixel
width is not content.

**Adherence to Vertical Slice Architecture.** All work lands in three already-coupled
locations that respect existing import direction:
1. the shared primitive `components/ui/data-table.tsx` (gains opt-in props, defaults off);
2. the `content-toolbar` slice (the density control lives beside the existing visibility
   and rows controls in `settings-menu.tsx`);
3. the `content-list` page that owns the view state and wires (1) to (2).
No new cross-slice import is created. `content-toolbar` already imports nothing from
`content-list`; the page passes plain props down, exactly as it does today for
`pageSize`/`columnVisibility`.

**Why ephemeral state, not persistence.** `content-list.tsx` carries an explicit standing
TODO ("load and save view configuration at the user level *when a user preferences system
exists*"). Per YAGNI, this sprint matches the existing pattern: `columnSizing` and
`density` become page-level React state that resets on navigation/remount — identical
lifecycle to today's `pageSize` and `columnVisibility`. No `localStorage`, no preferences
table. When the preferences system lands, all four states migrate together in one slice.

----------------------------------------------------------------------
TASK 4.1 — New density constants module (`lib/density.ts`)
----------------------------------------------------------------------
Single source of truth; consumed by both the table and the settings control. Keep the
"normal" row height equal to today's `48` so existing layout (and the exported
`ROW_HEIGHT_PX`) is unchanged when density is omitted.

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2024–2026 Flavio De Musso. All rights reserved.

export type TableDensity = "compact" | "normal" | "comfortable"

export const DEFAULT_DENSITY: TableDensity = "normal"

/** Row height in px per density. "normal" MUST stay 48 (== legacy ROW_HEIGHT_PX). */
export const DENSITY_ROW_HEIGHT: Record<TableDensity, number> = {
  compact: 36,
  normal: 48,
  comfortable: 64,
}

/** Tailwind padding utility applied to TableCell per density. */
export const DENSITY_CELL_PADDING: Record<TableDensity, string> = {
  compact: "py-1",
  normal: "py-2",
  comfortable: "py-3",
}
```

TASK 4.3 — DataTable primitive (`components/ui/data-table.tsx`)
----------------------------------------------------------------------
**4.3.a — Props.** Extend `DataTableProps<TData, TValue>` (after `onRowDoubleClick`):

```ts
import type { ColumnSizingState } from "@tanstack/react-table"
import { type TableDensity, DEFAULT_DENSITY, DENSITY_ROW_HEIGHT, DENSITY_CELL_PADDING } from "@/lib/density"

  /** Abilita il ridimensionamento colonne (default: false). */
  enableColumnResizing?: boolean
  /** Larghezze colonne controllate dall'esterno (opzionale). */
  columnSizing?: ColumnSizingState
  /** Callback al cambio larghezze colonne (modalità controllata). */

  /** Densità righe (default: "normal"). */
```

**4.3.b — Controlled/uncontrolled sizing state.** Mirror the existing
`columnVisibility` hybrid pattern (`L188–L191` + handler `L275–L293`):

```ts
const [internalColumnSizing, setInternalColumnSizing] =
  React.useState<ColumnSizingState>({})
const isControlledColumnSizing = columnSizingProp !== undefined
const columnSizing = columnSizingProp ?? internalColumnSizing

const handleColumnSizingChange = React.useCallback(
  (updaterOrValue: ColumnSizingState | ((old: ColumnSizingState) => ColumnSizingState)) => {
    const next = typeof updaterOrValue === "function" ? updaterOrValue(columnSizing) : updaterOrValue
    if (!isControlledColumnSizing) setInternalColumnSizing(next)
    onColumnSizingChange?.(next)
  },
  [columnSizing, isControlledColumnSizing, onColumnSizingChange]
)
```

**4.3.c — Table config** (inside `useReactTable`, `L365`):

```ts
enableColumnResizing,
columnResizeMode: "onChange",
onColumnSizingChange: handleColumnSizingChange,
// add to state: { … }
columnSizing,
```

**4.3.d — Density-driven row height.** Replace bare `ROW_HEIGHT_PX` usages with a
resolved local. At the top of the component body:

```ts
const activeDensity = density ?? DEFAULT_DENSITY
const rowHeight = DENSITY_ROW_HEIGHT[activeDensity]
const cellPadding = DENSITY_CELL_PADDING[activeDensity]
```
- Virtualizer `estimateSize: () => rowHeight` (was `ROW_HEIGHT_PX`, `L426`).
- Every `style={{ height: ROW_HEIGHT_PX }}` → `style={{ height: rowHeight }}`
  (`L449`, `L484`, `L631`).
- Keep the exported `ROW_HEIGHT_PX = 48` constant untouched for external importers.

**4.3.e — Cell padding (density).** In `renderRow`, add `cellPadding` to the
`TableCell` className via `cn(...)` for both the plain and context-menu branches
(`L502`, `L511`). Group-header cell keeps `py-0`.

**4.3.f — Width styles + resize handle.** Only when `enableColumnResizing`:
- Header loops (`L537–L545` and `L599–L607`): give each `<TableHead>`
  `style={{ width: header.getSize() }}` and, for resizable headers, append a handle:
  ```tsx
  <TableHead key={header.id} style={{ position: "relative", width: header.getSize() }}>
    {header.isPlaceholder ? null : flexRender(header.column.columnDef.header, header.getContext())}
    {enableColumnResizing && header.column.getCanResize() && (
      <button
        type="button"
        aria-label={/* t("toolbar.settings.resizeColumn") */ "Resize column"}
        onMouseDown={header.getResizeHandler()}
        onTouchStart={header.getResizeHandler()}
        className={cn(
          "absolute right-0 top-0 h-full w-1 cursor-col-resize select-none touch-none",
          "bg-transparent hover:bg-border",
          header.column.getIsResizing() && "bg-primary"
        )}
      />
    )}
  </TableHead>
  ```
- Cells in `renderRow`: add `style={{ width: cell.column.getSize() }}` to each
  `<TableCell>` when `enableColumnResizing`.
- Group-header `colSpan` cell (`L452`) is left untouched (spans all columns).

Factor the two near-identical header loops through a small local `renderHeaderGroups()`
helper to avoid divergence (optional but recommended; both branches already duplicate the
loop today).

# Sprint Documentation

**UniversalElementFormatting** (Sprint 5 of 6, "Saved Views") introduces the harness's Element contract: `compileElementFormatter()` in `apps/dashboard/src/lib/conditional-format.ts` turns an instance's conditional-format rules into a pure `ElementFormatter` (`entry → ElementFormat`), threaded through `ViewRendererProps.formatElement` and compiled once per rule-set change in `content-view-workspace.tsx`. Each View Type now maps that same semantic format to its own visuals: Table via a new `toTableRowStyles` adapter in `content-table-renderer.tsx` (evaluation moved out of `useContentTableConfig`, which is now purely table-derived state), Gallery and Kanban by carrying `elementStyle`/`slotStyles` on their display models, built once where those models are already constructed. The dashboard's rule vocabulary was renamed `row|cell` → `element|field` to match the already-persisted API vocabulary, deleting a translation layer in `view-config-mapping.ts`. The conditional-colours editor (previously Table-only) is now available on Gallery (`settings: [..., "conditionalFormats", ...]`) and Kanban (`settings: ["conditionalFormats"]`). No core, API, migration, or permission file was touched — dashboard-only, as scoped. Deliberately out of scope: the gallery cover image, category-folder card, kanban media slot, and the drag-overlay ghost get no formatting.

Known limitation logged by this review: the browser-based runtime walk (SECTION 5 step 8) was not performed, for the same reason the execution stage logged — substituted with component-level render-test evidence (RTL, real DOM, real class assertions) rather than a full `pnpm beech dev` click-through.

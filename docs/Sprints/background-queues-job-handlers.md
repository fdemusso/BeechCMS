# Sprint 7 — Background Queues & Job Handlers (`IQueueService`)

> Generated by the Sprint Planning stage. Verified against the `graphify` graph (8108 nodes / 18615 edges, rebuilt 2026-06-22) and the BeechCMS invariants in `_config/ponytail_arch.md`.

> **Ponytail pre-flight (architectural VETO applied to the brief):**
> - **VETO — dual-provider abstraction (Cloudflare Queues *and* Upstash QStash in v1).** YAGNI + Cloudflare Purity (rule 4). The interface stays provider-agnostic so QStash can be added later, but exactly **one** edge-native concrete implementation (Cloudflare Queues) plus an in-memory dev/test fallback ships now. QStash already exists in the repo only as a *notification publisher* (`apps/api/src/shared/qstash-notification-service.ts`); it is **not** reused or extended here.
> - **VETO — raw `db` / `bucket` in the job handler signature** (as written in the brief's example `async (payload, { db, bucket })`). Handing a raw `D1Database` to developer code violates **THE BOTANICAL INVARIANT** (rule 2): all D1 access must flow through `@beech/core`. The `JobContext` therefore exposes the engine-mediated `ContentRepository` and `BeechBucket` ports — never `env.DB`.
> - **APPROVED (minimalist blueprint):** zero new runtime dependencies in `@beech/core`; one new binding (`QUEUE`); contracts in core, single concrete impl + middleware in api; consumer handler mirrors the existing `scheduled()` handler. **HANDOFF -> caveman_coder.**

==========================================================================
SECTION 1 — WHY THIS SPRINT EXISTS FIRST
==========================================================================

Edge workers (`apps/api`) have a hard per-request CPU budget. Any developer-defined custom route (`BeechConfig.customRoutes`) that needs heavy or long-running work (bulk export, fan-out email, CRM sync) currently has nowhere to offload it. This sprint adds the **deferred-execution port** so that work can be *enqueued* from a request and *consumed* outside the request lifecycle.

It must be built as a self-contained contract-first slice, in this order, for three architectural reasons:

1. **It is a new tier-crossing primitive — the contract must be frozen before any job exists.** Like `IScheduler` (`packages/core/src/scheduler.interface.ts`) and `INotificationService`, the *port* (`IQueueService`) belongs in `@beech/core` as a **zero-dependency interface**. Concrete runners (`apps/api`) depend on the port, never the reverse. Defining the contract first is what lets the enqueue side (request handlers) and the consume side (the `queue()` export) be developed against a stable type without a circular dependency.

2. **The Botanical Invariant forces the handler context to be engine-mediated.** A background job is still a database participant. If we shipped jobs with raw `env.DB`, every future job author could bypass `apiToDb`/`dbToApi` and hardcode `content_{slug}` field names — exactly what rule 2 forbids. By specifying `JobContext` to carry `ContentRepository` (already the only sanctioned D1 path) up front, the invariant is preserved *by construction* for every job ever written.

3. **VSA: the dispatch logic is shared infrastructure, not a feature slice.** Enqueue (inside `customRoutes`) and consume (the `queue()` worker export in `index.ts`) are two call sites of the same registry. Per rule 3, that shared logic lives in `apps/api/src/shared/` + a middleware, **not** inside `apps/api/src/features/*`. No feature slice imports another.

**YAGNI posture:** no QStash path, no priorities, no dead-letter UI, no retry-policy DSL, no D1-backed job table (Cloudflare Queues already persists + retries). One binding, one interface, one runner, one in-memory fallback.

### 4.1 `packages/core/src/queue.interface.ts` (NEW — zero deps)

```ts
// SPDX-License-Identifier: MIT
// Copyright (c) 2024–2026 Flavio De Musso

import type { ContentRepository } from './content.repository.js'
import type { BeechBucket } from './storage.js'
import type { IClock } from './clock.js'
import type { IIdGenerator } from './id-generator.js'

/**
 * The envelope put on the wire / queue. `name` selects the handler from the
 * JobRegistry; `payload` is the developer-supplied, JSON-serializable body.
 */
export interface QueueMessage<T = unknown> {
  name: string
  payload: T
}

/**
 * Execution context handed to every job. Botanical Invariant: jobs receive the
 * engine-mediated repository, NEVER a raw D1Database. `env` is a read-only,
 * stringly-typed view of bindings/secrets for things like fetch targets — it
 * deliberately does not expose `DB`.
 */
export interface JobContext {
  repository: ContentRepository
  bucket: BeechBucket
  clock: IClock
  idGenerator: IIdGenerator
  env: Record<string, string | undefined>
}

/** A single background worker. Receives the decoded payload + context. */
export type JobHandler<T = unknown> = (
  payload: T,
  context: JobContext,
) => Promise<void>

/** Name -> handler map, supplied via BeechConfig.jobs. */
export type JobRegistry = Record<string, JobHandler<any>>

/**
 * Producer port. `enqueue` schedules deferred work and returns once the message
 * is accepted by the transport. Like INotificationService, implementations MUST
 * decide their own fire-and-forget vs inline semantics and MUST NOT let a
 * transport failure crash the request that called enqueue.
 */
export interface IQueueService {
  enqueue<T>(name: string, payload: T): Promise<void>
}
```

### 4.4 `apps/api/src/shared/cloudflare-queue-service.ts` (NEW)

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2024–2026 Flavio De Musso. All rights reserved.
// See LICENSE in the repository root for license terms.

/// <reference types="@cloudflare/workers-types" />
import type { IQueueService, QueueMessage } from '@beechcms/core'

/**
 * Production producer. Sends a QueueMessage envelope onto the Cloudflare Queue
 * binding. Cloudflare guarantees at-least-once delivery + retries on the
 * consumer side, so enqueue only needs to hand off the message.
 */
export class CloudflareQueueService implements IQueueService {
  constructor(private readonly queue: Queue<QueueMessage>) {}

  async enqueue<T>(name: string, payload: T): Promise<void> {
    try {
      await this.queue.send({ name, payload } satisfies QueueMessage<T>)
    } catch (error) {
      // Never crash the originating request (contract parity w/ notifications).
      console.error(`CloudflareQueueService: failed to enqueue "${name}"`, error)
    }
  }
}
```

### 4.5 `apps/api/src/shared/in-memory-queue-service.ts` (NEW)

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2024–2026 Flavio De Musso. All rights reserved.
// See LICENSE in the repository root for license terms.

import type { IQueueService, JobRegistry, JobContext } from '@beechcms/core'

type ScheduleBackgroundTask = (task: Promise<unknown>) => void

/**
 * Dev/offline + test fallback used when the QUEUE binding is absent. Runs the
 * matching handler in-process. In production this is never selected. Uses
 * executionCtx.waitUntil when available so enqueue stays non-blocking; falls
 * back to awaiting inline (tests) otherwise.
 */
export class InMemoryQueueService implements IQueueService {
  constructor(
    private readonly jobs: JobRegistry,
    private readonly context: JobContext,
    private readonly scheduleBackgroundTask?: ScheduleBackgroundTask,
  ) {}

  async enqueue<T>(name: string, payload: T): Promise<void> {
    const handler = this.jobs[name]
    if (!handler) {
      console.error(`InMemoryQueueService: no handler registered for "${name}"`)
      return
    }
    const run = handler(payload, this.context).catch((error) => {
      console.error(`InMemoryQueueService: job "${name}" failed`, error)
    })
    if (this.scheduleBackgroundTask) {
      this.scheduleBackgroundTask(run)
      return
    }
    await run
  }
}
```

### 4.6 `apps/api/src/shared/queue-consumer.ts` (NEW)

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2024–2026 Flavio De Musso. All rights reserved.
// See LICENSE in the repository root for license terms.

/// <reference types="@cloudflare/workers-types" />
import { SystemClock, SystemIdGenerator } from '@beechcms/core'
import type { JobRegistry, JobContext, QueueMessage } from '@beechcms/core'
import { D1ContentRepository } from './content.repository.d1'
import { resolveBucket } from './storage-resolver' // existing helper used by storageMiddleware
import type { Env } from '../types'

/**
 * Consumer-side dispatch. Mirrors index.ts `scheduled()`: builds an
 * engine-mediated JobContext from bindings (NEVER exposes env.DB to jobs) and
 * routes each message to its handler. ack() on success/unknown-name (drop),
 * retry() on throw so Cloudflare re-delivers.
 */
export async function dispatchQueueBatch(
  batch: MessageBatch<QueueMessage>,
  env: Env,
  _ctx: ExecutionContext,
  jobs: JobRegistry,
): Promise<void> {
  const context: JobContext = {
    repository: new D1ContentRepository(env.DB),
    bucket: resolveBucket(env),
    clock: SystemClock,
    idGenerator: SystemIdGenerator,
    env: env as unknown as Record<string, string | undefined>,
  }

  for (const message of batch.messages) {
    const { name, payload } = message.body
    const handler = jobs[name]
    if (!handler) {
      console.error(`[queue] no handler for "${name}" — dropping message`)
      message.ack()
      continue
    }
    try {
      await handler(payload, context)
      message.ack()
    } catch (error) {
      console.error(`[queue] job "${name}" failed — will retry`, error)
      message.retry()
    }
  }
}
```

### 4.7 `apps/api/src/middleware/queue.middleware.ts` (NEW)

```ts
// SPDX-License-Identifier: BUSL-1.1
// Copyright (c) 2024–2026 Flavio De Musso. All rights reserved.
// See LICENSE in the repository root for license terms.

/// <reference types="@cloudflare/workers-types" />
import { createMiddleware } from 'hono/factory'
import { SystemClock, SystemIdGenerator } from '@beechcms/core'
import type { IQueueService, JobRegistry, JobContext, QueueMessage } from '@beechcms/core'
import type { AppEnv } from '../types'
import { CloudflareQueueService } from '../shared/cloudflare-queue-service'
import { InMemoryQueueService } from '../shared/in-memory-queue-service'

export interface QueueOverrides {
  queue?: IQueueService
}

/**
 * Injects `queue` into context. Must run AFTER repositoryMiddleware and
 * storageMiddleware: the in-memory fallback builds a JobContext from
 * `repository` + `bucket` already present in context.
 */
export const queueMiddleware = (jobs: JobRegistry = {}, overrides?: QueueOverrides) => {
  return createMiddleware<AppEnv>(async (context, next) => {
    let scheduleBackgroundTask: ((task: Promise<unknown>) => void) | undefined
    try {
      const executionContext = context.executionCtx
      scheduleBackgroundTask = executionContext.waitUntil.bind(executionContext)
    } catch {
      scheduleBackgroundTask = undefined
    }

    let queue: IQueueService
    if (overrides?.queue) {
      queue = overrides.queue
    } else if (context.env.QUEUE) {
      queue = new CloudflareQueueService(context.env.QUEUE as Queue<QueueMessage>)
    } else {
      const jobContext: JobContext = {
        repository: context.get('repository'),
        bucket: context.get('bucket'),
        clock: SystemClock,
        idGenerator: SystemIdGenerator,
        env: context.env as unknown as Record<string, string | undefined>,
      }
      queue = new InMemoryQueueService(jobs, jobContext, scheduleBackgroundTask)
    }

    context.set('queue', queue)
    await next()
  })
}
```

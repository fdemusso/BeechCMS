Beech Design System

The UI contract for apps/dashboard. Every rule is a plain sentence, every token has a name, a value and a Tailwind class. Follow it when you build or change any screen; the lint (pnpm lint:design) enforces the mechanical part.

How to use this file

  • #rules is binding. MUST and NEVER mean what they say.
  • #lookup answers "which class do I write for X". Start there.
  • #design-tokens (the JSON block in the page head) is the machine-readable list of every token and value.
  • Source of truth. apps/dashboard/src/index.css MUST declare every token of the manifest with exactly those values. If a token named here is missing from index.css, declare it there; NEVER inline its value in a component.
  • Availability. Each component below is tagged exists, to extend or to create. Import the first kind, add the missing variants to the second, build the third at the path shown.
  • If this file has no answer, see #undecided. Do not invent a value: ask.

Rules

  1. Colour comes from tokens. NEVER write a Tailwind palette class (bg-emerald-50, text-amber-800), a hex or rgb() value, or an arbitrary colour (bg-[#fff]). Use the classes in #lookup.
  2. One filled primary Button per view. It is the action the page exists for (create, save, publish). Every other action is outline or ghost. Two default buttons in one view is a defect.
  3. Status has its own colours. Show a content or job status only with <StatusBadge> or the status-* tokens. NEVER use primary, signal or category to mean a status. A status panel background is bg-status-*-soft, NEVER bg-status-*/5 or any opacity of the solid: only -soft is computed for text contrast. A solid status fill (bg-status-*) is for dots, bars and icons, never behind text.
  4. Signal is a micro detail. Use it only for an unread count, a "new" marker, or a progress fill. NEVER on a button, a link, a heading, a chart or a status.
  5. Category organises. Use it for category and tag chips, the active navigation item, avatar fallbacks and illustrations. NEVER for selection, hover or status.
  6. Selection and hover are neutral. Selected row: bg-muted. Row hover: hover:bg-muted/50. Pressed or hovered on a quiet surface: bg-muted-strong. NEVER tint a selection with a brand colour.
  7. Links and titles are text colour. Emphasis comes from font-medium, and from an underline inside running text. NEVER a coloured link.
  8. Text on a solid brand fill is dark. text-signal-on on bg-signal, text-category-foreground on bg-category. NEVER white on those fills (2.9:1).
  9. Tint with oklab. A brand colour mixed into a grey uses color-mix(in oklab, …), or an opacity suffix (bg-signal/10). NEVER in oklch: it interpolates hue and pushes sand towards purple on tinted greys.
  10. Type sizes come from the scale. text-xs, text-sm, text-base, text-xl, text-2xl, text-4xl, text-5xl, chosen by role (see #typography). NEVER text-[10px]. text-lg and text-3xl do not exist. Weights are font-normal, font-medium, font-bold; NEVER font-semibold.
  11. Headings are Lora, bold. font-heading font-bold. Everything else is Geist.
  12. Radius has three levels. rounded-control for controls, rounded-lg for surfaces, rounded-full for chips and avatars. NEVER rounded-[7px].
  13. Text and icons. Every user-visible string goes through t("key") and exists in both locales/en.json and locales/it.json. Icons are imported from @/components/icons only.
  14. Check your work. After editing a file under apps/dashboard/src, run node scripts/check-design-tokens.mjs --format agent <file> and fix every line. A deliberate exception takes // design-ok: <reason> on the same or previous line.

Colour roles

Five roles. Each has one job and a ceiling. Neutrals cover about 90% of any screen, ink about 8%, signal and category together a few details.

Neutral

Surfaces, lines, text and every transient state. Seven levels per theme: card (raised), background (page), muted, muted-strong, border, muted-foreground, foreground. Hue 286°, chroma at most 0.016.

Use for backgrounds, borders, text, row selection, hover, table headers, tracks. Never add a new grey: secondary, accent and the sidebar tokens are aliases of the levels above.

Ink · primary

The action colour: #3F3D56 in light, a lilac #b3b1cf in dark, chosen so the contrast (9.58:1) is the same in both themes. The text on it is the opposite theme's background.

Use for the single filled Button of a view, a checked checkbox or switch, the focus ring, the logo. Never for secondary buttons, links, selection, or status.

Signal · coral

Attention. Always small. Solid #FF6584 (dark text on it), soft background with signal-foreground text, and signal-strong for progress fills.

Use for an unread count, a "new" marker, a progress fill. Never for buttons, links, headings, charts, or any status. Its hue (11°) is close to the error red (31°): NEVER place signal next to an error message.

Category · sand

Organisation. #DEA684, soft tint for chips and the active navigation item, dark text #3a2412 on the solid.

Use for category and tag chips, collection labels, the active sidebar item, avatar fallbacks, empty-state illustrations. Never for selection, hover, or the state of a content item, and never next to a warning (sand and amber are close).

Status

Functional colours, separate from the brand: live, warning, danger, info. neutral has no colour of its own: it is muted with muted-foreground. Each status has a solid (same in both themes), a soft background and a foreground text colour.

StatusContent / job statesExample

--destructive (the shadcn token) is the same value as --status-danger.

Technical rules

  • Tint with color-mix(in oklab, …) or an opacity suffix, NEVER in oklch.
  • Dark theme: ink inverts to the lilac, status text brightens, signal and category stay the same. Do not hand-write dark: colour classes for tokens: the variable already changes with the theme.
  • A dot or icon that carries meaning has a text label beside it. Colour is never the only signal.

Charts

Multi-series charts use chart-1 to chart-5, in order. They are categorical: ink, sand, teal, olive, plum at low chroma, so none of them can be mistaken for a status or for the coral signal. Each holds 3:1 on the card in both themes and every pair is at least 0.12 apart in OKLab. MUST pick series colours only from these five. NEVER colour a series with status-* unless the series is that status (published vs failed). More than five series: group the tail into "Other" in grey (text-muted-foreground). The palette is for data, never for chrome.

Motion

One rule: entering takes 220ms, leaving takes 20% less (176ms). Things that appear are noticed; things that go are not waited for.

TokenValueClass
--duration-enter220msduration-(--duration-enter)
--duration-exit176ms (calc(var(--duration-enter) * 0.8))duration-(--duration-exit)
  • MUST pair them on every layer that mounts and unmounts (dialog, sheet, popover, dropdown, tooltip, toast): data-open:duration-(--duration-enter) data-closed:duration-(--duration-exit) with fade-in-0 / fade-out-0.
  • MUST fade the scrim and the surface together, with the same two durations.
  • NEVER write a literal duration-100, duration-300 or duration-[…ms] in a component. Change the token, not the call site.
  • Hover and focus colour changes are not entrance animations: they keep the library default and need no token.

Components

Import from @/components/ui/… unless a path says otherwise. Do not rebuild a component that exists.

Button exists

import { Button } from "@/components/ui/button"

  • Variants: default (ink fill, the primary action), outline, secondary, ghost, destructive (soft red fill), link.
  • Sizes: default 32px, xs 24, sm 28, lg 36, and square icon, icon-xs, icon-sm, icon-lg.
  • One default per view, usually in PageHeader actions or the dialog footer. Toolbar and secondary actions are outline or ghost.
  • An icon-only button MUST have aria-label and a Tooltip.
  • destructive belongs in a confirmation (ConfirmDialog), not as a standing button in a toolbar.
<PageHeader title={t("articles.title")} actions={<Button onClick={create}>{t("articles.create")}</Button>} />
<Button variant="outline">{t("common.export")}</Button>

Badge to extend

import { Badge } from "@/components/ui/badge"

  • Exists: default, secondary, destructive, outline, ghost, link.
  • Add category (bg-category-soft text-foreground) and signal (bg-signal-soft text-signal-foreground) to badgeVariants.
  • category for tags and collection labels. signal for "new". A count on the navigation uses solid bg-signal text-signal-on.
  • Do not use the destructive badge for a failed item: use StatusBadge. default (ink) competes with the primary button: use sparingly.
<Badge variant="category">{entry.category}</Badge>

StatusBadge to create

components/ui/status-badge.tsx · the only way to show a content or job status.

  • Props: status: "published" | "draft" | "scheduled" | "failed" | "archived", optional className. The label comes from t(`status.${status}`).
  • Mapping: published → live, draft → warning, scheduled → info, failed → danger, archived → neutral.
  • Anatomy: a 7px dot (bg-status-X) and the label on bg-status-X-soft text-status-X-foreground, h-5 rounded-full px-2 text-xs font-medium. Neutral uses bg-muted text-muted-foreground.
  • Replace every hand-written green, amber or red badge with it.
const STATUS = {
  published: { tone: "live" },
  draft:     { tone: "warning" },
  scheduled: { tone: "info" },
  failed:    { tone: "danger" },
  archived:  { tone: "neutral" },
} as const

<StatusBadge status={entry.status} />

Pill exists

import { Pill } from "@/components/ui/pill" · a rounded chip with an optional main action and an optional secondary action (remove, dismiss).

  • Variants: secondary, outline, primary, destructive. Use for filters and removable selections in toolbars, not for status or category.
  • primary is ink: it counts toward the one-filled-element-per-view budget.
<Pill label="Status" trailing={3}
  action={{ icon: <Trash2 />, label: t("filters.remove"), tone: "destructive", onClick: remove }} />

TagChip, TagChips, IconBadge exists

  • TagChips (@/components/ui/tag-chips) renders the value of a tags field: option tags filled with the option colour, free tags neutral, values no longer in the options as a dashed outline.
  • IconBadge (@/components/ui/icon-badge) is a 24px square badge with one icon and a tooltip: roles, permissions, scopes.

Forms exists

Field, FieldLabel, FieldDescription, FieldError, FieldGroup, FieldSet, FieldLegend from field; Input, Textarea, Select*, Checkbox, Switch, InputGroup*.

  • Every control has a visible FieldLabel. A placeholder is a hint, never the label.
  • Validation text goes in FieldError, which renders text-status-danger-foreground. It is shown with the control, not only in a toast.
  • Switch applies immediately (settings). Checkbox is a value submitted with the form or a row selection.
  • A form has one default Button (submit) and an outline cancel.
<Field>
  <FieldLabel htmlFor="title">{t("entry.title")}</FieldLabel>
  <Input id="title" {...register("title")} />
  <FieldError>{errors.title?.message}</FieldError>
</Field>

Card exists

Card, CardHeader, CardTitle, CardDescription, CardAction, CardContent, CardFooter. A raised surface (bg-card rounded-lg border). Never nest a card in a card. Settings pages do not use cards: see SettingsSection.

Overlays exists

  • Dialog: a short form or a focused task. Sheet: a side panel for details or a longer form. Both sit on bg-scrim.
  • ConfirmDialog (@/components/ui/confirm-dialog) wraps AlertDialog: props open, onOpenChange, title, description, confirmVariant, onConfirm. Use confirmVariant="destructive" for irreversible actions.
  • Popover for rich floating content, DropdownMenu for a list of actions, Tooltip for a name on an icon or a short hint. A tooltip never holds an action.

Tables and lists exists

  • Entry lists use DataTable (@/components/ui/data-table). Plain Table parts are for small static tables.
  • Header bg-muted, header text text-xs font-medium text-muted-foreground, row hover hover:bg-muted/50, selected row bg-muted.
  • Status column: StatusBadge. Category column: Badge variant="category". Row titles: text-foreground font-medium, never coloured.

Tabs, Breadcrumb, Pagination, Kbd exists

Tabs, TabsList, TabsTrigger, TabsContent switch views of the same object. Breadcrumb* shows the path in nested pages. Pagination* pages long lists. Kbd and KbdGroup show keyboard shortcuts. The active tab and the current breadcrumb are neutral, never tinted.

Empty states, Skeleton, toasts exists

  • Empty, EmptyHeader, EmptyMedia, EmptyTitle, EmptyDescription, EmptyContent from @/components/ui/small-cta. Every empty list says what is missing and offers the one action that fills it. Sand (bg-category-soft) may colour the illustration.
  • Skeleton shaped like the content while it loads. A spinner (Loader) only inside a button.
  • Toasts use sonner (toast.success, toast.error). A toast confirms an action that already happened; an error that blocks a form also appears in that form.

Page layout exists

import { AppShell, PageBody, PageHeader } from "@/features/navigation"

  • Every page is AppShell → PageBody → PageHeader (title, description, actions) → content. The header holds the page's one primary Button.
  • Settings pages use SettingsSection (id, title, description, action) and SettingsRow from @/components/ui/settings-section: sections drawn straight on the page, a border between rows, no cards.

Permissions

A user without the permission does not see the action: hide the Button or show the state without the action (the empty state above omits EmptyContent when onCreate is absent). Hiding is cosmetic: the API enforces it.

node scripts/check-design-tokens.mjs --format agent <file...>  # one line per violation, with the fix

Working loop

  1. Edit a file under apps/dashboard/src.
  2. Run the agent format on it and fix every line.
  3. Run it again until it prints nothing for that file.

Exceptions

Add // design-ok: <reason> on the same or the previous line. Legitimate reasons: a colour chosen by the user and stored as data, vendor code you do not own, an image overlay gradient. "It looked better" is not a reason.

Undecided

Not defined yet. Do not invent a value for these: reuse the nearest existing component's classes, or ask.

  • Shadows. No shadow tokens. Floating layers (popover, dialog) use their component's existing shadow.
  • Easing. No easing token. Durations are defined (see Motion); curves use the library default.
  • Stacking. No z-index scale.
  • Monospace font. No declared stack for code.
  • Line height scale. Use the component's existing line height.
  • Scrim values. 30% / 50% are a starting point, to be tuned on a real dialog.

Before you finish

  • No palette class, hex, rgb() or arbitrary colour in the diff.
  • One default Button per view.
  • Status shown with StatusBadge or status-* tokens only.
  • Signal and category used only for the jobs above.
